# 旅记 TripFlow


一个出行计划工具 - 把分散在小红书收藏夹里的吃喝住行攻略，整合成一个可调整的行程时间轴。

## 背景

这款工具，是结合自己在英国留学、频繁欧洲短途出游的亲身经历设计的。很多留英学生都有同款经历：和朋友临时约好周末去欧洲邻国旅行。

过去做攻略的体验很差：如果和朋友一起规划，大家会把小红书看到的攻略、想去的餐厅景点全都发到聊天群，内容五花八门，想去的地方大量重复，很难统一筛选合并，看似分工合作，实则几个人重复做了大半工作，越整理越混乱；就算自己单独做攻略，小红书上的游记零散杂乱，没有配套的路线地图，存下一大堆笔记之后，翻看、对照都很麻烦，就算挨个在谷歌地图标记位置，最后依旧要自己反复琢磨先后顺序，规划出来的路线经常绕路、走回头路。

而这个产品就是针对性解决这些问题：用户刷到心仪的景点、餐厅，可以随时录入收藏；全部意向地点收录完毕后，按需划入对应日期行程，清晰看到每日游玩体量；用户可以以入住酒店为起点，结合所有点位地理位置，智能规划连贯、少折返的出行路线；后续增减收藏、调整行程顺序，地图路线会实时自动更新，不用再手动标记、反复修改路线，让短途旅行攻略从杂乱繁琐变得高效清晰。

## 解决什么问题

做出行攻略时，我们会在小红书刷到很多景点、餐厅、拍照角度，随手收藏后堆在收藏夹里混乱不堪。用户真正要出发时，往往还要重新查地点、确认地址、判断哪些地点适合放在同一天，再手动安排路线顺序。到了景点现场，经常会忘记"这个地方可以干什么""这个地方可以怎么拍"，有时还不一定找得到自己想要的那个攻略。

**TripFlow** 把这些零散的收藏整理成：
- 按 **城市 / 类型** 分类的卡片墙（景点、餐厅、住宿、其他）
- 每张卡片可记录 **出片指南**（添加你想要拍的照片）
- 可拖拽调整顺序的 **行程时间轴**
- 当天路线的 **地图可视化**（景点间连线 + 距离参考）

## 使用方式

**`https://qiuuuyanping.github.io/-TripFlow/tripflow.html`**  
  即可在浏览器中打开使用，无需安装任何东西。
  这是单文件版本，所有 JS 都内嵌在 HTML 里，不依赖外部文件。

## 功能说明

### 1️⃣ 出行概览
- 出行标题、日期、天数、途经城市
- 出行提醒
- 各城市收藏统计

### 2️⃣ 我的收藏
- 按城市分组的卡片墙
- 多种类型：景点  / 餐厅  / 住宿  / 其他 
- 每张卡片包含：名称、地址、坐标、备注、**照片提醒**、标签
- 支持增删改

### 3️⃣ 行程轴
- 按天规划行程
- 每个行程绑定一个收藏项
- **可拖拽调整顺序**（拖动 ⠿ 图标）
- 显示与下一站的距离参考
- 按时间自动排序

### 4️⃣ 地图路线
- 使用 Leaflet + OpenStreetMap
- 当天行程的景点在地图上标号显示
- 景点间虚线连线
- 点击标记查看详情
- 路线列表 + 总距离参考

## 数据存储

所有数据存在浏览器 **localStorage** 中，不依赖后端。
- 数据只存在当前浏览器，换设备/清缓存会丢失
- 概览页提供"恢复示例数据"和"清空所有数据"按钮

## 示例数据

内置一份"罗马3日游"示例数据，包含：
- 8 个收藏（斗兽场、梵蒂冈博物馆、特莱维喷泉、万神殿、圣天使堡、2家餐厅、1家酒店）
- 3 天完整行程安排

## 技术栈

| 技术 | 用途 |
|------|------|
| HTML + Tailwind CSS (CDN) | 页面结构和样式 |
| 原生 JavaScript | 所有交互逻辑 |
| Leaflet + OpenStreetMap | 地图可视化 |

## 文件结构

```
/workspace
├── tripflow.html   # 单文件版
├── index.html      # 页面骨架（需配合 app.js 使用）
├── app.js          # 全部应用逻辑
└── README.md       # 本文档
```

> **为什么有两个版本？**
> - `tripflow.html` = 单文件版，JS 内嵌在 HTML 里
> - `index.html` + `app.js` = 分离版，需要通过本地服务器打开（直接双击会被浏览器 CORS 拦截）
> - 日常使用选 `tripflow.html`；要改代码时选分离版更好维护
